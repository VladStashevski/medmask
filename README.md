# MedMask

Настольная программа для локального обезличивания папки с медицинскими
документами. Сервер, браузер, авторизация, облачное хранилище и сетевые запросы
отсутствуют.

## Как работает готовая программа

1. Пользователь запускает MedMask.exe в Windows или MedMask.app в macOS.
2. Выбирает папку с историями и нажимает «Обезличить».
3. На экране виден список документов папки: у каждого свой значок — ожидает,
   обрабатывается, готов, требует проверки или ошибка. Снизу идут этап, общий
   прогресс, проценты и время.
4. Рядом создается папка «Обезличенные».
5. Исходные файлы остаются без изменений, а результаты получают безопасные
   имена document_0001.pdf, document_0002.pdf и так далее.
6. В новой папке создается _ОТЧЁТ.txt без исходных имен и фрагментов
   медицинского текста.

Пользователю не нужно устанавливать Python или библиотеки: они включаются
в автономную сборку.

Готовые файлы для Windows и macOS находятся в разделе Releases репозитория.
Оба артефакта — zip-архивы: в Windows распакуйте папку и запустите
MedMask.exe, в macOS перенесите MedMask.app в «Программы».

## Форматы

Поддерживаются PDF, JPG, JPEG, PNG, TIFF, BMP, WEBP, DOCX, RTF, ODT, ODG, TXT,
XLSX и XLSM. Все результаты пересобираются как новые текстовые PDF без исходных
метаданных, аннотаций, форм и изображений.

Маскируются ФИО пациентов и медработников, даты рождения, адреса, телефоны,
email, СНИЛС, ИНН, паспортные данные, полисы, места работы и номера медицинских
карт. Дата рождения заменяется рассчитанным возрастом.

PDF-сканы и изображения распознаются встроенным OCR с поддержкой кириллицы.
Модели входят в приложение: интернет, Python и отдельный Tesseract пользователю
не нужны. Исходная картинка в результат не копируется — сохраняется только
распознанный и обезличенный текст. Страницы с низкой уверенностью OCR отдельно
помечаются в отчете.

Шрифт для итоговых PDF (Liberation Sans) тоже входит в сборку, поэтому результат
не зависит от того, какие шрифты установлены в системе, и совпадает в Windows
и macOS.

Автоматические правила не дают абсолютной гарантии. Перед передачей документов
итоговые PDF необходимо просмотреть.

## Производительность и контроль обработки

- Текстовые документы и OCR-задачи обрабатываются в отдельных ограниченных
  пулах. Число OCR-процессов выбирается по CPU и физической памяти, поэтому
  приложение не запускает много тяжёлых моделей одновременно.
- Огромные изображения уменьшаются до рабочего разрешения до передачи в OCR;
  обычные страницы A4 по-прежнему распознаются при 180 DPI.
- Интерфейс показывает общий прогресс, прошедшее и примерное оставшееся время,
  а список отмечает каждый документ по мере готовности и сам прокручивается
  к тому, который обрабатывается. Во время запуска кнопка «Обезличить»
  становится кнопкой «Отменить».
- При отмене незавершённая выходная папка удаляется, исходники остаются без
  изменений. Для диагностического последовательного запуска можно задать
  `MEDMASK_DISABLE_PARALLEL=1`.

Воспроизводимый замер на тестовом корпусе запускается так:

~~~bash
.venv/bin/python scripts/benchmark_corpus.py /путь/к/набору \
  --work-root /private/tmp/medmask-benchmark
~~~

Скрипт сначала копирует входные данные, а JSON-отчёт не сохраняет исходные
имена, пути и фрагменты документов. Параметр `--baseline previous.json`
дополнительно требует точного совпадения извлечённого текста, числа страниц,
OCR-предупреждений и результатов автоматического аудита.

## Пакетный режим

Тот же движок доступен из командной строки — это используют смоук-тест сборки
и автоматизация:

~~~bash
python main.py --batch /путь/к/папке        # из исходников
dist/MedMask.app/Contents/MacOS/MedMask --batch /путь/к/папке   # macOS
dist\MedMask\MedMask.exe --batch C:\путь\к\папке                # Windows
~~~

Команда печатает путь к созданной папке и возвращает ненулевой код при ошибке.

## Интерфейс

Окно построено на PySide6 и Qt Quick. Python отвечает за обработку файлов и
состояния, QML — за внешний вид, переходы и анимацию. Движок обезличивания в
интерфейсе не дублируется: окно вызывает тот же `medmask.batch`.

- `medmask/gui/qml/MedMask/Theme.qml` — единственный набор токенов: палитра,
  шкала отступов, радиусы, размеры шрифтов, высоты элементов и длительности;
- `medmask/gui/qml/MedMask/` — компоненты `GlassPanel`, `PillButton`,
  `FileRow`, `StatusIndicator`, `ProgressPanel`, `FolderBar`, `TitleBar`,
  `DocumentList`, `EmptyState`. `FolderBar` и `ProgressPanel` — пилюли одной
  высоты: у нижней этап, проценты, время, полоса и кнопки стоят в одну строку,
  и в узком окне первой уступает полоса, затем подпись этапа;
- `medmask/gui/controller.py` — состояния окна и подписи к ним;
- `medmask/gui/models.py` — список документов для QML;
- `medmask/gui/worker.py` — обход папки и обработка в отдельных потоках, чтобы
  окно не замирало во время OCR.

Список держит в сцене только видимые строки, поэтому папка на тысячу
документов открывается так же быстро, как папка на десять. Строка, которая
обрабатывается прямо сейчас, подсвечивается и подтягивается в видимую часть.

Матовое стекло — не картинка, а размытый слепок того, что лежит под пилюлей:
строки списка уходят под них и видны сквозь стекло. Список обрезан не по
прямой, а по силуэту самой пилюли: у капсулы концы скругленные, и прямая
обрезка выпускала бы наружу край строки с ее углом. Стекло выключается само,
если система просит высокий контраст или сцену рисует процессор; тогда пилюли
становятся непрозрачными, а верстка не меняется. Принудительно режимы
переключаются переменными `MEDMASK_GLASS=off` и `MEDMASK_MOTION=off`.

Маски и там, и там сделаны через `MultiEffect`, и у обеих порог отсечения
задан явно: при `maskThresholdMin: 0` эффект не отсекает ничего — пикселей
«ниже нуля» не бывает, и маска молча висит вхолостую.

Тема одна — светлая, за системной она не следует: медицинский документ читают
с белого листа. В macOS окно принудительно держит светлое оформление, поэтому
в темной теме системы светофор и меню окна тоже остаются светлыми.

Окно — одна поверхность от края до края, без карточек и без отдельной полосы
заголовка: список идет во всю его высоту, а папка сверху и состояние снизу
лежат на нем двумя пилюлями одной высоты. Строки списка повторяют их: те же
поля по бокам и такая же капсула, поэтому подсветка строки и пилюли стоят на
одной вертикали.

Верхняя полоса окна отдана системным кнопкам. В macOS системная
рамка остается, но становится прозрачной (`fullSizeContentView`) и светлой:
светофор стоит прямо на панели, а полноэкранный режим, перетаскивание и
изменение размера — родные. В Windows системная полоса снимается, окно
показывает свои кнопки, а перетаскивание и размер отдаются родным циклам
системы, поэтому работают прилипание к краям и Snap Layouts. Вернуть обычную
рамку можно через `MEDMASK_NATIVE_FRAME=1`.

Клавиши: `Cmd/Ctrl+O` — выбрать папку, `Cmd/Ctrl+Enter` — запустить или
остановить, `Esc` — отменить обработку, `Cmd/Ctrl+Shift+O` — открыть результат.
Кнопки обходятся с клавиатуры, у выбранной видно кольцо фокуса.

Прежнее окно на tkinter осталось в `medmask/app.py` как запасное: оно
открывается по `MEDMASK_UI=tk` и тогда, когда PySide6 в системе нет.
В нативный релиз оно не входит: Qt поставляется вместе с приложением, поэтому
дублирующий Tcl/Tk там не нужен.

Посмотреть все состояния окна, не запуская обработку:

```bash
python scripts/preview_ui.py --out preview --size 760x600
QT_SCALE_FACTOR=1.5 python scripts/preview_ui.py --out preview-150
```

## Общий код и сборки

Движок и интерфейс общие для обеих систем. Релиз собирает
`scripts/build_native.py` нативным компилятором Nuitka:

- Windows x64: `scripts/build_windows.ps1` создает `dist\MedMask\MedMask.exe`
  и архив `dist\MedMask-Windows-x64-<версия>.zip`;
- macOS Apple Silicon: `scripts/build_macos.command` создает `dist/MedMask.app`
  и архив `dist/MedMask-macOS-<версия>.zip`.

Оба скрипта после сборки прогоняют `scripts/smoke_test.py`: он запускает готовое
приложение на тестовом документе и проверяет, что PDF создан, персональные
данные исчезли, а клинический текст остался.

Перед компиляцией `pyside6-rcc` сжимает QML и изображения интерфейса в ресурс
Qt. Nuitka встраивает этот ресурс и Python-модули MedMask в исполняемый файл.
После сборки удаляются исходники, type stubs, отладочные символы и служебные
метаданные; `scripts/verify_protected_build.py` не позволяет упаковать артефакт,
если такие файлы остались. Это усложняет анализ программы, но не является
абсолютной защитой от реверс-инжиниринга.

Важно: закрытая поставка содержит PyMuPDF. Для её распространения требуется
коммерческая лицензия Artifex; альтернативный путь — соблюдать AGPL и открыть
соответствующий исходный код, что противоречит цели защищённой сборки. Поэтому
публикация по тегу заблокирована, пока в настройках GitHub не установлена
переменная `PYMUPDF_COMMERCIAL_LICENSE_CONFIRMED=true`.

Версия хранится в одном месте — `medmask/__init__.py`; pyproject, Info.plist и
имена архивов берут ее оттуда.

Сборка требует Python только у разработчика. Workflow
`.github/workflows/build-desktop.yml` собирает оба артефакта, прогоняет тесты и
смоук-тест и по тегу `v*` публикует Release, сверив тег с версией пакета.

## Локальная разработка

~~~bash
python3 -m venv .venv
.venv/bin/python -m pip install -c constraints.txt ".[build]"
.venv/bin/python scripts/test_all.py
.venv/bin/python main.py
~~~

`constraints.txt` фиксирует проверенные версии прямых и транзитивных
зависимостей, чтобы локальная и CI-сборка не менялись из-за свежего релиза
OCR-, PDF- или упаковочной библиотеки.

Тесты разделены по назначению:

- `tests/test_batch.py` — обход папки, отчет, прогресс, отдельные правила движка;
- `tests/test_engine_pii.py` — утечки персональных данных и порча клинического
  текста на реальных сценариях;
- `tests/test_gui.py` — состояния окна, список документов, загрузка QML и
  полный проход по настоящему движку;
- `tests/test_ui.py` — запасное окно на tkinter: обрезка длинных имен и путей,
  переходы и верстка при системном масштабе 100-200 %;
- `tests/test_packaging.py` — встроенные ресурсы, лицензии, единая версия.
